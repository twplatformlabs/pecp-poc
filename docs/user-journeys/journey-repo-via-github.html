Back-stage actions
  • Repo is created tied to the user — no team associated
  • Naming convention validated / enforced OPEN Q1
  • repository.created webhook fires into the platform engine
  • Platform engine auto-registers the repo under the user
  • The webhook has already associated the repo to the user in the platform engine
  • Recorded as a base, non-AI repo (Phase 1)
  • Platform engine continues to monitor and manage the repo under the user
  • Repo stays base — no AI capabilities in Phase 1
  • repository.deleted webhook fires into the platform engine
  • Platform engine tears down and cleans up everything associated with the repo OPEN Q6
  • (Likely Phase 2) audit / evidence record of the deletion retained for Compliance

Open questions

Q2 ✓
Resolved — auto-team. A repo created via GitHub is user-owned with no team. There is no auto-team on repo creation; team creation is its own first-class flow (Flow 3).
Q10 ✓
Resolved — AI on user repos. Phase 1 user-owned github repos are base repos, no AI. AI capabilities are provisioned only through the control-plane team-repo flow (Flow 5). A Phase 2 flow may let users add AI to their own repos — see below.
Q1
Naming convention. With no team, what's the pattern for a user repo — username/repo-name? What enforces it: a GitHub ruleset, or the webhook?
Q3
Registration purpose. The webhook already registers the repo. Now that AI-unlock is out of Phase 1, is a manual claim/registration step still needed here — and what does it accomplish?
Q6
Cleanup on delete. What does cleanup cover — retained audit/evidence for Compliance?
Q7
Access levels. Org write / Enterprise read — confirm. Repo-level permission for the creator — admin?
Q8
Non-admin delete. Ask the repo admin directly, or a control-plane request? Own mini-flow?
Q9
SSH. Only supported auth? Where is the key provisioned in onboarding?

Front-stage actions
  • Runs a CLI command (or asks an MCP agent) to create a project under the team
  • Names the project; confirms the team association OPEN Q1
  • Watches the scaffold progress — no manual wiring
  • Sees dev, qa, and prod appear as environments
  • Sees the project + three environments ready; the app-of-apps repo is available
  • Can now manage secrets, add a datastore, deploy, expose, or promote
Launchpad: this anchor flow hands off to every other Phase 2 journey.
Back-stage actions
  • Platform engine validates the user's rights on the team (RBAC)
  • Records the project under the team — 1:1 to start; can become many-teams later OPEN Q2
  • Self-service — no approval to create a project OPEN Q3
  • Creates the JFrog project space (artifact isolation by project) OPEN Q4
  • Creates the unified secret / config space for the project OPEN Q5
  • Creates the platform-owned app-of-apps repo (default GitOps scaffold) OPEN Q6
  • Auto-provisions dev + qa in the nonprod cluster/account, prod in the separate prod cluster/account
  • Each env: namespace + default resource quota, config/secret binding, JFrog pull config (imagePullSecrets injected), GitOps wiring (Argo watches app-of-apps)
Boundary: prod is a separate cluster in a separate AWS account — not just another namespace. Static-stability isolation per the account-topology ADR.
  • Platform engine records the project + environments as the central source of truth across integrated systems

Open questions

Q1
Project naming. Naming convention for projects, and how duplicate-project scenarios are handled.
Q2
Many teams per project. When does the 1:many team↔project relationship get enabled, and what does shared ownership look like?
Q3
Approval. Confirm project provisioning is fully self-service with no approval gate in Phase 2.
Q4
JFrog structure. Naming / folder layout of the JFrog project space; isolation is by project — how are collisions avoided?
Q5
Secret/config backend. The unified store's backend — GitHub secrets vs Vault / 1Password — is still being decided.
Q6
App-of-apps repo. Naming, and whether it's a dedicated repo under the project or a path within one. Possibly it belongs at the team level instead — it can span all of a team's projects. Left open for now.
Q7
Default quotas. What the default ResourceQuota / LimitRange values are per environment tier.

Phase 2 flow set

1 · Provision project & environments this map
The anchor — creates the project, spaces, and dev/qa/prod.
2 · Manage secrets & config next
Set and read secrets/config in the unified store.
3 · Create a custom environment to map
Add staging / uat beyond the auto-provisioned three.
4 · Add a datastore to map
CLI-provision or manifest/operator — tied to an environment.
5 · Deploy app to dev / qa to map
Build → JFrog → GitOps sync → running.
6 · Expose a service to map
Domain + mesh + certificate.
7 · Promote to production to map
The compliance / admission gate — the crown jewel.
8 · Migrate a project in last
Bring an external workload onto the platform.

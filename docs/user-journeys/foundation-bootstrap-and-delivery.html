01

Platform Bootstrap

manual · by hand
One repo, not two. The task isn't "bootstrap GitHub" or "bootstrap AWS" — it's bootstrap the platform; GitHub and AWS are just the first two providers, each a module. Combining them makes the one true cross-provider dependency explicit: the AWS OIDC trust consumes the GitHub org identity the GitHub module produces. Thin, pure IaC, local state (it can't use the state bucket it hasn't created yet).

Stage definitions

Plan
Check run against live infra — what will change and how.
Pre-deploy
Pre-deploy tests. Validate any logic inside the IaC itself, via mocks, before applying.
Static
Static checks — one button. Bundles fmt/validate, tflint, security scan (tfsec/Checkov), policy-as-code (OPA/Conftest), secret scan (gitleaks), and cost (Infracost). Runs in parallel with Plan and Pre-deploy.
Publish
Persist the plan output somewhere durable (e.g. JFrog) for the approver.
Approval
Manual gate before any apply.
Apply
Apply the published plan output.
Post-apply
Post-Apply Hooks — new. Imperative glue Terraform can't express — e.g. kubectl against the fresh cluster, provider API calls, readiness waits. Scaffolded even when empty.
Post-deploy
Post-deploy tests. Smoke + E2E validation of what was just provisioned.

Open questions

Q1
Bootstrap credentials. A combined apply needs GitHub org-admin and AWS admin creds in one run. Acceptable, or split the modules back out if different teams own each / to keep privileged creds from coexisting?
Q2
Post-apply boundary. What legitimately belongs in Post-Apply Hooks vs. being pushed into a controller/GitOps? Guardrails so it doesn't become a dumping ground for un-tested imperative steps.
Q3
State key convention. Within the central state account — bucket/key/workspace layout per repo × account.
Q4
Static-checks blocking policy. Which checks hard-fail the pipeline vs. report-only (e.g. Infracost, some policy rules)?
Q5
OSS & custom pipelines (scaffolds). Where do they live, and how do they meet the GitOps app-of-apps and the P2·07 prod compliance gate? Plus upstream-bump trigger (Renovate) and signing/attestation policy.

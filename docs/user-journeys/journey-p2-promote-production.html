Front-stage actions
  • Promotes the tested artifact to prod — points the prod app-of-apps at the qa-proven image
  • Confirms the human-in-the-loop step (promotion is a destructive/prod action) OPEN Q6
  • Waits on the admission gate — nothing to do but pass it
  • Sees the evidence recorded against the deploy
  • Pass: sees the service live in prod
  • Fail: sees the specific reasons and fixes them
On reject the consumer sees why — e.g. image not signed, missing scans, low/no test validation — and re-runs after fixing. No exceptions initially. OPEN Q5
Back-stage actions
  • Platform engine routes the promotion toward the prod cluster/account
  • Human-in-the-loop confirmation required (also when driven via AI/MCP)
  • The admission gate validates the artifact's compliance evidence:
  • Image signed — start with cosign OPEN Q1
  • SBOM present & valid — the goal state OPEN Q1
  • Scans / test evidence as policy expands OPEN Q4
Enforced by admission — K8s admission controller, and/or an Argo pre-sync hook, and/or a JFrog Xray policy. No proof → rejected. OPEN Q2
  • Validated evidence is stored as the audit record for the deploy
  • Feeds the SNOW integration for prod deploys OPEN Q3
  • Pass: Argo syncs into the prod cluster/account; workload runs
  • Fail: sync is blocked; the deploy is rejected with reasons returned

Open questions

Q1
Evidence type. Start with a cosign signature, build toward SBOM — confirm the sequencing and SBOM format (CycloneDX vs SPDX) when it lands.
Q2
Enforcement point(s). Which of admission controller / Argo pre-sync / Xray policy is authoritative, and whether checks are layered across all three.
Q3
SNOW integration. How stored evidence flows into ServiceNow for the prod change record — shape and timing.
Q4
Policy taxonomy. Beyond signature/SBOM — scans, license, test-coverage thresholds — what's the compliance taxonomy and how does it grow?
Q5
Exceptions. None initially. When introduced, who approves — Product Owner or department manager? (needs investigation)
Q6
HITL via AI. The promotion confirmation when driven through an agent — how the human-in-the-loop step is presented and audited ("user via Claude").

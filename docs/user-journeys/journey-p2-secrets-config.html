Open questions

Q1
Store backend. The unified store's backend — GitHub secrets vs Vault / 1Password. The lean is away from GitHub toward a more robust manager. This decision shapes the whole flow.
Q2
Direct-write audit. When a user writes straight into the tool (Lane B), can the platform capture the same audit trail as the CLI path? Under investigation — and it may gate whether Lane B is allowed.
Q3
External Secrets wiring. Which backend does the External Secrets Operator read from, and how is it configured per namespace? Depends on Q1.
Q4
Scoping & keys. Project-wide vs per-environment values, key naming convention, and how per-env overrides work.
Q5
Config vs secret handling. Same store for both (confirmed) — but are they handled identically, or is config lower-sensitivity with different access?
Q6
Build-time vs runtime. Does this cover build-time secrets (for GitHub Actions builds) too, or only runtime secrets consumed in-cluster?
Q7
Rotation. Who owns rotation, and does a rotated value auto-resync into the namespace?

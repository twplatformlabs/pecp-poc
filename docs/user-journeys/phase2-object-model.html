Reading the model

Project is the anchor. Repos, the JFrog space, and the config/secret space hang off it — shared across the project's environments.
Environments are flat. Each gets the same wiring at provision time: namespace, config/secret binding, JFrog pull config, GitOps.
Cluster/account is a detail. Structurally it's just an environment; the cluster and account it lands in are attributes of that environment (prod → prod cluster/account).
Add-ons attach to an environment. domain, certificate, and database come as follow-on capabilities.

Cardinality & open points

Team ↔ Project is many-to-many — a team owns many projects, a project can be run by many teams. Both start 1:1.
Project → Repositories is 1:many — this supersedes Phase 1's "team-owned repo"; repos now hang off the project.
Open — JFrog structure. Naming/folder layout of the JFrog project space, and how duplicate-project scenarios are handled.
Open — secret/config store. One unified store is the intent; the backend (GitHub secrets vs Vault / 1Password) is still being decided.

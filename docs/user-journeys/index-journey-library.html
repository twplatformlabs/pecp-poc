Decision Log

resolved to date
The design decisions the maps are built on — settled enough to draw, open enough to revisit.

Phase 1 · GitHub

P1
Source of truth is both. GitHub and the platform engine are both valid edit surfaces; sync is bidirectional. The platform engine is the central, up-to-date record across integrated systems.
P1
Teams bypass Entra. Phase 1 GitHub teams have no Entra group backing; only Enterprise + org access ties to AD groups.
P1
AI on team repos only. AI capabilities attach solely to platform-engine team repos — not user-owned repos (adding AI to those is a Phase 2 preview).
P1
No auto-team on repo creation. Creating a repo never implicitly creates a team; the two are independent acts.

Phase 2 · Deployment

P2
Project is the anchor. A new Project object owns repos, JFrog space, and config; Team ↔ Project is many-to-many (1:1 to start). Environments are flat siblings.
P2
Prod is isolated. Prod runs in a separate cluster in a separate AWS account — a static-stability boundary per the account-topology ADR. Cluster/account is a per-environment detail.
P2
Compliance verifies at deploy. The platform validates evidence at the prod admission gate (cosign → SBOM) rather than generating it — it doesn't own the build pipeline.
P2
Datastore approval asymmetry. CLI-provisioned DBs need team-lead approval (no git trail); manifest/operator DBs are self-service because the PR is the audit artifact.

Open Questions

by theme
Consolidated across the library — every amber flag on the maps rolls up to one of these.

Phase 1 themes

Naming & access
  • Conventions for repo and team names; reserved names.
  • Access levels confirmation across personas; SSH provisioning timing.
AI & compliance catalog
  • Full AI capability catalog and the complete compliance level taxonomy.
  • Guided questionnaire content and approval-policy logic.
Governance
  • Team deletion handling for owned repos; whether manual repo registration is still needed given webhook auto-registration.
  • Out-of-band creation — enforce vs nudge posture.

Phase 2 themes

Secrets & config
  • Store backend — GitHub secrets vs Vault / 1Password (cascades widely).
  • Direct-write audit and External Secrets wiring per namespace.
Datastore & networking
  • Operator — Crossplane vs custom; teardown & prod DB static stability.
  • ExternalDNS approach; mesh opt-out path; east-west mTLS & DR.
Compliance & migration
  • Evidence & enforcement — cosign→SBOM sequencing, which admission point is authoritative, SNOW integration, exception policy.
  • App-of-apps level (team vs project); migration build-vs-buy per capability.

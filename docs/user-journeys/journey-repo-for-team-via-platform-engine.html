Front-stage actions
  • Opens the platform engine, chooses Create repository
  • Selects the owning team — the repo will be team-owned OPEN Q1
  • Names the repo per the convention OPEN Q2
  • Answers the guided questions:
    • Does it need AI integration? Which capabilities? OPEN Q4
    • What compliance level? OPEN Q5
    • Other options to tailor the repo OPEN Q3
The differentiator: this guided setup is the value of Flow 5 over a github-created repo — the right AI & compliance posture is chosen up front, not wired later.
  • Sees the repo created — team-owned, live in the platform engine and GitHub
  • Team members clone via SSH; read, write, update OPEN Q6
  • Use GitHub normally, inside the org
  • Deletes via the platform engine (or GitHub if a repo admin)
Back-stage actions
  • Platform engine confirms the user's rights on the selected team
  • Presents the guided creation flow
  • Answers drive the repo template, AI capabilities, and compliance posture
  • Compliance governs which AI capabilities are offered for the declared level OPEN Q5
  • Platform engine creates the repo and ties ownership to the team (team has access) OPEN Q7
  • Applies AI capabilities + compliance posture; registers everything
  • Projects the repo to GitHub with team permissions; idempotent wiring
  • Out of scope for Phase 1: CI/CD, secrets, observability, deploy envs
  • Platform engine monitors and manages the repo under the team
  • AI capabilities live; team permissions enforced
  • repository.deleted sync → platform engine cleanup; AI deregistered OPEN Q8
  • (Likely Phase 2) audit / evidence record retained for Compliance

Open questions

Q1
Who can create. Any team member, or only the owner/admins? Must a repo always belong to a team in this flow (yes by definition — confirm there's no user-owned option here)?
Q2
Naming convention. Is it team-name/repo-name? Same rule as the GitHub-created path, or does the platform engine apply its own?
Q3
Full questionnaire. Beyond AI & compliance, what else does it ask — visibility, description/metadata, template? (Note: starter kits are out of scope for Phase 1 — confirm none here.)
Q4
AI catalog. The concrete Phase 1 AI capabilities and how the questionnaire maps answers to them.
Q5
Compliance levels. What are the discrete levels, and how do they gate which AI capabilities are offered? This is where compliant vs non-compliant is cleanly decided — unlike a user-owned repo (Flow 2 Q5/Q10).
Q6
Team access model. Does "team has access" mean all members get write? How do owner/admin/maintainer roles map to repo permissions?
Q7
Ownership record. How is team ownership represented — a GitHub team-repo permission, a platform-engine association, or both kept in sync?
Q8
Cleanup on delete. Same as the other flows — AI deregistration, retained audit/evidence for Compliance.
